# SWP 재고관리 0.3.0

Windows 매장 PC용 설치형 프로그램입니다. **로컬 테스트**와 **SWP 매장 연결**을 구분합니다. 실제 스마트스토어 개설과 API 검증은 별도로 필요하며, 키가 없으면 연결 완료로 표시하지 않습니다.

## 실행 파일

- `release/SWP-Inventory-0.3.0-x64-nsis.exe`: Windows x64 설치 프로그램
- `release/SWP-Inventory-0.3.0-x64-portable.exe`: 설치 없이 실행

Node·Java·DB 서버를 사용자 PC에 별도로 설치할 필요는 없습니다. 매장 모드는 실행 중인 SWP API 서버가 필요합니다. 코드 서명이 없는 빌드입니다.

## 로컬 테스트

최초 실행은 빈 SQLite DB로 시작합니다. 상품 등록·검색·입출고·실사 조정·전체/상품별 이력·백업을 사용할 수 있습니다. DB 위치는 이전 버전과 같은 `%APPDATA%\SWPInventoryTest\test\inventory.sqlite`입니다. 설치형과 portable이 같은 Windows 사용자에서 같은 데이터를 사용합니다.

0.3.0에서는 **상품 등록 → 게임·상품명·언어 입력 → 공식 이미지 검색 → 이 이미지 선택 → 상품 등록** 순서로 이미지를 저장합니다. 등록한 이미지는 상품 목록과 재고 상세에 표시되고 재시작 후에도 유지됩니다. 검색은 인터넷 연결이 필요하며 별도의 Java·웹 서버는 필요하지 않습니다. 원피스 한국어판, Flesh and Blood 영어판, 리프트바운드 한국어판을 지원합니다. 번호·세트·판본을 확인해 선택하세요.

기존 DB는 상품과 재고 이력을 보존하며 자동 확장합니다. 기존 0.2.0 실행 파일에는 이 화면이 없으므로 프로그램을 닫고 0.3.0 설치 파일로 업데이트하거나 새 portable을 실행하세요. 테스트 상품을 자동으로 넣지는 않습니다.

입고·출고는 증감 수량, 실사는 **변경 후 목표 수량**을 입력합니다. 정수만 허용하며 상한은 99,999,999입니다. 음수 재고·중복 코드·중복 요청·오래된 수량 덮어쓰기를 차단합니다. 변경 사유·이전/이후 수량을 기록합니다.

## SWP 매장 연결

1. SWP 웹사이트에 관리자로 로그인합니다.
2. **상점 관리 → 재고관리 앱**에서 기기 이름과 일회성 연결 코드를 발급합니다.
3. 프로그램의 **매장 서버 연결**에서 서버 주소·기기 이름·연결 코드를 입력합니다.
4. 매장 모드와 서버 주소를 확인하고 상품을 조회합니다.
5. 입출고를 저장하면 같은 SWP 서버의 판매가능 재고와 이력이 바뀝니다. 웹 주문·취소도 같은 재고를 사용합니다.

공개 서버는 HTTPS를 사용합니다. HTTP는 이 PC의 localhost/127.0.0.1/[::1]만 허용합니다. 주소는 origin 또는 `/shop-api`까지 입력합니다. 연결 코드는 5분간 한 번만 사용하며 기기 권한은 서버에서 만료·해제할 수 있습니다.

기기 토큰은 Electron main 프로세스가 Windows 보안 저장소로 암호화해 저장합니다. 화면·브라우저·로그·Git에 토큰을 전달하지 않습니다. 저장 연결이 손상되면 오류를 표시하고 매장 모드를 유지합니다. 통신 실패 시 로컬 DB로 자동 전환하지 않습니다.

두 모드 사이에 상품·재고를 복사하거나 합치지 않습니다. 매장 모드의 재고는 실제 서버 데이터입니다. 매장 상품 등록은 SWP 상점 관리자에서 진행하고, 매장 DB 백업은 서버 측에서 별도로 관리합니다.

## 스마트스토어

매장 모드에서 연결 상태, 상품·옵션 조회, 상품 매핑, 초기 기준 검수, 선택 상품 일괄 동기화 결과를 확인합니다. 상품명으로 자동 연결하지 않으며 원상품·옵션번호와 세트·언어·컨디션·판매 단위를 확인해야 합니다.

API 비밀키는 서버에만 설정합니다. 초기 기준과 기존 미출고 주문을 확인하고 주문 수집·대사를 통과한 상품만 송신합니다. 반품·교환·부분 수량 변경은 자동 입고하지 않습니다. 미설정·차단·충돌·실패·결과 불명확은 반영 완료가 아니며, 결과 불명확 요청은 자동 재전송하지 않습니다.

설정·개설·배포·제한은 [통합 운영 안내](../docs/inventory-integration.md)를 참고하세요. 실제 네이버 스토어 개설과 라이브 검증 전에는 실연동 완료로 간주하지 않습니다.

## 백업

로컬 DB는 SQLite WAL을 사용하므로 실행 중 파일 하나만 복사하지 말고 **DB 백업 저장**을 이용하세요. 기존 파일은 덮어쓰지 않습니다. 복원 UI는 없습니다. 복원 전 현재 DB와 `-wal`, `-shm`을 함께 보존하고, 빈 별도 데이터 폴더에서 백업을 먼저 검증하세요.

## 개발·검증·빌드

Node.js 24+, Windows x64 기준입니다. 이 프로젝트 폴더에서 실행합니다.

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run test:desktop
npm.cmd run test:images
npm.cmd start
npm.cmd run package
```

저장소 루트의 `./scripts/build-shop.ps1`로 웹/API JAR를 빌드한 뒤, Java 21을 선택한 터미널에서 이 폴더의 `npm.cmd run test:store`를 실행하면 실제 통합을 검증합니다. 새 메모리 H2 서버와 임시 세션·상품만 사용하며 운영 DB를 사용하지 않습니다.

`test-output/`, `.local/`, DB, 백업, `release/`는 Git 제외입니다. 별도 개발 DB 실행은 빌드 후 `.\node_modules\.bin\electron.cmd . --data-dir=.local/manual-test`로 가능합니다. 패키징된 프로그램은 데이터 경로 재지정을 허용하지 않습니다.
