# SWP 재고관리 — 설치형 1차 버전

매장 PC 한 대에서 사용하는 Windows용 **로컬 테스트 프로그램**입니다. 기존 SWP store와 별도 패키지·빌드·SQLite DB를 사용합니다. 이 폴더만 별도로 복사해도 개발·빌드할 수 있으며, 상점의 Java 서버·Neon·H2·환경 파일을 읽지 않습니다.

## 현재 범위

- 빈 상품 목록에서 시작합니다. 자동 예시 데이터는 없습니다.
- 상품 코드(SKU)·상품명·세트·언어·컨디션·판매 단위·초기 재고 등록
- 상품명·상품 코드·세트의 부분 검색과 페이지 조회
- 입고, 출고, 실사 수량 조정과 필수 변경 사유
- 상품별·전체 재고 이력: 이전 수량, 증감, 이후 수량, 사유, 시각
- 음수·소수·상한 초과 차단, 중복 SKU 방지, 중복 요청 방지, 버전 충돌 검사
- SQLite 트랜잭션 저장, 재시작 후 보존, DB 스냅샷 백업

**스마트스토어·기존 SWP store·결제·주문·배송은 연결되지 않았습니다.** 초기 버전은 테스트 프로필만 제공하며 실매장 재고 원장으로 전환하는 절차는 후속 단계에서 검증합니다. 인터넷 연결이나 별도 호스팅 없이 실행합니다.

## 실행 파일

빌드 후 `release/`에 다음 파일이 생성됩니다. Git에는 실행 파일·DB·백업을 포함하지 않습니다.

- `SWP-Inventory-Test-0.1.0-x64-nsis.exe`: Windows x64 설치 프로그램
- `SWP-Inventory-Test-0.1.0-x64-portable.exe`: 설치 없이 실행하는 버전

실행 파일에는 필요한 런타임이 포함되어 사용자 PC에 Node·Java·DB 서버를 별도로 설치할 필요가 없습니다. 이 빌드는 코드 서명이 없는 로컬 검증용 빌드입니다.

## 사용 순서

1. 프로그램을 실행하고 **테스트 DB** 표시를 확인합니다.
2. 상품 등록에서 SKU와 상품 정보를 입력합니다. 같은 이름이어도 세트·언어·컨디션·판매 단위가 다르면 다른 SKU로 등록합니다.
3. 상품을 검색하고 선택합니다.
4. 입고·출고는 증감할 수량을, 실사 조정은 **최종 목표 수량**을 입력합니다. 변경 사유를 입력한 뒤 저장합니다.
5. 재고 이력에서 이전 수량과 이후 수량을 확인합니다.
6. DB 백업으로 새 파일에 백업합니다. 기존 파일은 덮어쓰지 않습니다.

입출고 수량은 양의 정수, 초기·실사 수량은 0 이상 정수이며 최대 99,999,999입니다. 현재 수량과 동일한 실사는 변경 이력을 만들지 않습니다. SKU의 영문 대소문자는 구분하지 않습니다. 충돌 시 최신 수량을 다시 확인해야 하며 자동으로 덮어쓰지 않습니다.

## DB와 백업

기본 데이터 위치는 `%APPDATA%\SWPInventoryTest\test\inventory.sqlite`입니다. 설치형과 portable은 같은 Windows 사용자에서 이 테스트 DB를 사용합니다. 실행 파일 옆이나 설치 폴더에는 DB를 저장하지 않습니다. 화면에서도 DB 경로를 확인할 수 있습니다.

SQLite WAL을 사용하므로 실행 중 `.sqlite` 파일만 복사하지 말고 **DB 백업** 기능을 이용하세요. 백업 대상에는 사용자 데이터가 포함되므로 Git에 추가하지 마세요. DB를 지우면 상품·이력이 사라집니다. 프로그램 삭제 시 DB를 자동 삭제하지 않습니다.

백업 복원 UI는 이번 범위에 없습니다. 수동 복원이 필요하면 프로그램을 완전히 종료한 뒤 현재 DB와 `-wal`, `-shm` 파일을 별도 폴더에 함께 보존하고, **비어 있는 별도 데이터 폴더**에 백업을 복사해 먼저 검증하세요. 기존 DB 위로 바로 덮어쓰지 마세요.

## 개발·검증·빌드

Node.js 24 이상, npm, Windows x64를 기준으로 합니다. 명령은 모두 이 프로젝트 폴더에서 실행합니다.

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run test:desktop
npm.cmd start
```

개발 확인용 별도 데이터 폴더를 지정하려면 다음처럼 실행합니다. 패키징된 프로그램은 데이터 경로 재지정을 허용하지 않습니다.

```powershell
npm.cmd run build
.\node_modules\.bin\electron.cmd . --data-dir=.local/manual-test
```

```powershell
npm.cmd run package
```

첫 패키징에는 Electron·Windows 패키징 도구 다운로드를 위한 인터넷 연결이 필요합니다. 실행 중에는 외부 네트워크 요청을 차단합니다.

`npm test`는 임시 SQLite DB에서 도메인 규칙을 검증합니다. `npm run test:desktop`은 `test-output/`의 별도 DB에서 실제 Electron 런타임·preload·IPC·재시작 보존·백업을 검증합니다. 이 데이터는 기본 앱 DB나 기존 상점 DB에 들어가지 않습니다.

## 후속 단계

1. 스마트스토어 상품·옵션 **읽기 전용** 조회 및 내부 SKU 매핑
2. 지정 상품의 수동 재고 반영과 결과·실패·재시도 표시
3. 온라인 주문·취소 수집, 중복 처리 방지, 동시 판매 충돌·재고 대사 검증
4. 자동 동기화 및 필요시 공통 재고 서비스로 확장

온라인 재고 연동은 네이버 API 사용 권한·공인 고정 IP 등을 확인한 후 진행합니다. 단순히 로컬 수량을 반복 전송하는 방식은 온라인 주문으로 감소한 수량을 덮어쓸 수 있으므로 사용하지 않습니다.
