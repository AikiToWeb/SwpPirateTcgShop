# 0.2.0 검증 기록

검증일: 2026-11-03. 독립 QA가 지정 구현 범위를 통과로 판정했습니다. 기존 운영 DB와 실제 네이버 계정에는 접근하지 않았습니다.

- Java 전체 60개 통과: 재고 API 12, 모의 HTTP 스마트스토어 17, 기존 회귀 31. Java 21·격리 메모리 H2 사용.
- 설치형 Node 테스트 27개 통과: 기존 재고 규칙과 HTTPS/loopback·암호화 경계·기기 인증·모드 격리·동시 요청·오류 처리.
- 실제 Electron 로컬 테스트 통과: SQLite·sandbox preload·IPC 송신자 경계·보존·백업·화면 마운트·화면 전환 회귀.
- `npm run test:store` 실제 통합 통과: 합본 Java JAR·메모리 H2·웹 관리자 화면에서 연결 코드 발급·Windows 실제 safeStorage 암호화/해독·Electron IPC·공통 재고·웹 주문/취소·버전 충돌·기기 폐기.
- 실제 재고 흐름: 웹 상품 등록 10 → 설치형 입고 5 → 재고 15 → 웹 주문 2 → 재고 13 → 주문 취소 → 15. 중복 요청과 오래된 버전은 추가 차감하지 않음.
- 별도 로컬 PostgreSQL 17에서 이전 스키마와 샘플 행을 먼저 생성한 뒤 새 JAR로 비파괴 스키마 추가 및 같은 실 통합 테스트 통과. 이전 샘플 수량 7 보존 확인. 공유 Neon을 사용하지 않았으며 테스트 컨테이너는 종료·정리함.
- 웹/설치형 빌드 및 합본 JAR 빌드 통과. Docker 이미지 빌드와 비루트 실행·빈 메모리 DB API·웹 HTTP 200 확인.
- 0.2.0 NSIS·portable 재패키징 성공. 빌드된 앱 실행 후 최종 추가 화면 자동 검사는 사용자의 Esc 입력으로 중단하여 추가 조작하지 않음. 앞선 실 API·웹 관리자·Electron 통합 결과와 구분함.
- QA가 발견한 연결 정보 손상 시 자동 로컬 전환, 연결 해제 파일 실패, 마지막 페이지 계산, baseline 차단 응답의 성공 표시, 상품 정체성 변경, 재고 상한 불일치를 수정·재검토함.

실제 네이버 API 인증·주문·재고 쓰기, 인터넷 공개 배포, 다른 PC의 설치/제거는 미검증입니다. 네이버 동일 상품 주문과 절대수량 쓰기의 경쟁 위험이 남으므로 송신은 기본 비활성화이며 실판매 동시성을 완전히 보장하지 않습니다. 초기 24시간 주문이 있는 매핑·부분 클레임·반품·교환·불명확 전송은 수동 검토가 필요합니다.

아래는 이전 0.1.0의 검증 기록입니다.

# 0.1.0 검증 기록

검증일: 2026-11-03. 기존 SWP store의 코드·환경 파일·DB는 변경하지 않았습니다. 아래 데이터는 임시 DB, `test-output/`, `.local/`의 별도 DB만 사용했습니다.

## 자동 검증

- `npm.cmd test`: 15/15 통과. 빈 시작, 상품 등록, 검색·와일드카드·페이지, SKU 중복, 정수/상한 검증, 입출고/실사 계산, 변경 없음, 재시도 멱등, 버전 충돌, 트랜잭션 롤백, 재시작 보존, WAL 백업 복원, 미래 스키마 버전 거부.
- `npm.cmd run test:desktop`: Electron 45.2.1에서 SQLite·sandbox preload·실제 IPC·다른 창의 IPC 거부·재시작 보존·백업 복원·React 마운트 통과.
- 이력 조회를 180ms 지연하고 30ms 후 상품 화면으로 이동하는 회귀: 수정 전 실패, 수정 후 통과. 상품 화면 새로고침 잠김 문제 해결.
- 960px 너비의 빈 화면: 문서의 수평 넘침 없음.
- `npm.cmd run build`: 통과.

## Windows 실제 화면

computer-use로 별도 `.local/ui-review` DB에서 확인했습니다.

- 최초 빈 상품 목록·0건 요약·테스트 DB·스마트스토어 미연동 표시
- 상품 등록 대화상자, SKU/이름/초기재고 입력, 등록 저장
- 초기 재고 10 → 입고 5 → 현재 재고 15 및 요약 갱신
- 상품별 이력 2건: 초기 등록 +10, 입고 +5, 변경 전후 10 → 15, 사유·시각 표시
- DB 백업 네이티브 저장 대화상자 열기 및 취소 후 화면 복귀

## 독립 QA

QA가 데이터 계층 테스트 15/15 및 최종 UI 빌드를 직접 확인했습니다. DB 분리, 트랜잭션, 입력 검증, IPC 경계, CSP, 비동기 상태를 검토했습니다. 발견한 P2 화면 전환 결함은 수정 후 재검토했으며 미해결 출시 차단 결함은 없습니다.

## 최종 패키지

- 최종 수정본의 `npm.cmd run package`로 NSIS 설치 프로그램과 portable EXE를 생성했습니다.
- `release/win-unpacked/SWP Inventory Test.exe`를 실제 실행했습니다. `resources/app.asar/index.html`에서 화면이 로드되고 기본 `%APPDATA%/SWPInventoryTest/test/inventory.sqlite`가 빈 상품 목록으로 열리는 것을 확인했습니다.
- 기본 앱 DB에는 검증용 상품을 등록하지 않았습니다. 수량 변경 화면 검증 데이터는 `.local/ui-review`에만 있습니다.

## 범위와 제한

- Windows x64 설치 프로그램과 portable 빌드입니다. 코드 서명은 없습니다.
- 네이티브 저장 대화상자에서 실제 파일명을 지정하여 저장하는 전체 흐름은 미검증입니다. 동일 백업 함수의 실제 SQLite 파일 생성·복원과 Electron IPC 환경의 백업은 자동 검증했습니다.
- 설치 프로그램으로 설치·제거하는 과정은 미검증입니다.
- 다른 PC/OS, 실매장 데이터, 스마트스토어, 기존 상점, 온라인 주문·취소·배송은 검증 범위가 아닙니다.
- 초기 버전은 로컬 테스트 프로필만 제공합니다. 기본 DB에 예시 상품을 자동 입력하지 않습니다.
