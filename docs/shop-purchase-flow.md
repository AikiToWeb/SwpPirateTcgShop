# 카드 등록·재고 관리·매장 수령 구매 신청

## 관리자

1. 기존 카카오 계정으로 로그인합니다. 서버에서 지정한 관리자에게만 **상점 관리**가 표시됩니다.
2. **상품 → 상품 등록**에서 상품 코드·이름·세트·게임·컨디션·언어·판매가·실물 재고를 입력합니다. 이미지 주소 입력 또는 공식 이미지 검색을 사용할 수 있습니다.
3. **판매 공개**를 선택해 저장하면 고객 목록에 표시됩니다. 비공개 상품은 고객이 주문할 수 없습니다.
4. **입출고**에서 증감 수량과 사유를 입력합니다. 주문 등으로 재고가 먼저 바뀌면 충돌을 표시하므로 새로고침 후 실물 수량을 확인합니다.
5. **주문**에서 주문번호·신청자 닉네임·회원번호·접수시각·상품·금액을 확인합니다. 상품을 전달한 뒤 **수령 완료 처리**합니다. 수령 완료 때 재고를 다시 차감하지 않습니다.

## 이용자

카드를 검색해 상세·가격·재고·구매 한도를 확인하고 장바구니에 담습니다. 카카오 로그인 후 **매장 수령 주문 접수**를 누르면 서버가 실제 가격·재고·계정별 누적 한도를 검사하고 주문을 접수합니다. 온라인 결제나 배송 신청은 포함하지 않습니다.

**주문 내역**에서 자신의 신청을 확인하고 접수 상태에서 취소할 수 있습니다. 취소 시 재고와 해당 주문의 구매 가능 수량이 복구됩니다. 수령 완료 주문은 고객 취소가 불가합니다. 관리자용 신청자 정보는 다른 고객의 API에 노출하지 않습니다.

장바구니는 재고 예약이 아닙니다. 담은 뒤 재고나 한도가 바뀌어도 기존 줄을 줄이거나 삭제할 수 있지만, 신규 담기·수량 증가·최종 주문은 서버에서 검사합니다. 재고 부족 등 주문 실패 시 최신 상품을 다시 조회하며, 응답 유실 시 같은 요청 키를 유지해 중복 신청을 방지합니다.

## 격리된 수동 검증

Java 21과 Maven 3.9 이상으로 웹을 빌드한 뒤 backend에서 `mvn package`를 실행합니다. 운영 설정 없이 테스트하려면 저장소 루트에서 아래 실행기를 사용합니다.

```sh
python3 scripts/review-shop.py --java /path/to/java21/bin/java
```

실행기는 임시 작업 폴더에서 합본 JAR를 실행합니다. `.env.shop`과 기존 DB를 읽지 않고 메모리 H2·합성 관리자/고객 계정만 사용합니다. 18081·18175는 비어 있어야 합니다.

- 관리자: `http://127.0.0.1:18175/__review/admin`
- 고객: `http://127.0.0.1:18175/__review/customer`

이 URL은 개발 검증 실행기에만 존재하며 실제 서버에는 추가하지 않습니다. 검증 페이지는 운영 사이트가 아닙니다. 테스트 데이터는 종료 시 소멸합니다. Ctrl-C로 검증 서버와 Java 프로세스를 함께 종료합니다. 테스트 계정은 카카오 연동 검증을 대신하지 않습니다.

## 2026-11-16 검증 결과

- 독립 QA: 메모리 H2에서 Java 전체 94개 테스트 통과, 실패·오류·생략 0. 인증·CSRF·계정 분리·동시 재고 보호·구매 한도 및 전체 신청 생명주기 포함.
- React production 빌드와 웹/API 합본 JAR 빌드 통과.
- 실제 브라우저: 빈 DB에서 관리자 카드 등록(재고 3) → 입고(+2) → 일반 이용자 구매 신청(1,500원) → 취소 → 재신청 → 관리자 신청자 확인·수령 완료 → 고객 취소 버튼 없음 확인.
- 재고 변경 회귀: 고객 장바구니 3개 상태에서 관리자 재고를 1개로 차감 후 고객이 3→2→1로 줄일 수 있고 증가 버튼은 비활성화됨을 확인.
- 운영 Neon DB·카카오 키·실제 스마트스토어는 사용하거나 변경하지 않음. 실제 카카오 로그인·운영 PostgreSQL·공식 이미지 외부 출처는 이번 검증 범위에 포함하지 않음.
