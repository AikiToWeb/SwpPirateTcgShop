# 다섯 역할 개발팀

프로젝트 운영의 기준 지침은 루트 `AGENTS.md`다. 이 문서는 역할 연결과 사용법을 설명한다.

```text
사용자 ⇄ PM (기본 채팅)
           ├─ 기획자 ⇄ PM
           ├─ 프론트 개발자 ⇄ PM
           ├─ 백엔드 개발자 ⇄ PM
           └─ QA ⇄ PM
```

전문가는 PM에게 질문·개선안·반대 의견·결함·장애를 전달할 수 있다. PM은 이를 검토해 다른 역할에게 전달하거나 사용자에게 필요한 질문만 통합한다. 전문가는 사용자와 별도 채팅을 만들지 않는다. 도구 실행 과정이 UI에 보이는 것까지 숨기는 설정은 아니다.

## 프로젝트 설정

- `.codex/config.toml`: 하위 에이전트 사용과 전문가 네 역할의 동시 실행 상한.
- `.codex/agents/pm.toml`: PM 행동 정의. 기본 채팅이 PM이므로 추가 PM을 실행하지 않는다.
- `.codex/agents/planner.toml`: 기획자.
- `.codex/agents/frontend.toml`: 프론트 개발자.
- `.codex/agents/backend.toml`: 백엔드 개발자.
- `.codex/agents/qa.toml`: QA.

모델·인증·권한·MCP 연결은 상위 세션에서 상속한다. 이 설정은 모델이나 전역 사용자 설정을 강제로 바꾸지 않는다. PM이 네 전문가를 직접 관리하며 전문가는 추가 에이전트를 만들지 않는다.

현재 도구가 사용자 정의 역할을 선택하는 인자를 제공하지 않는 경우에도 PM은 해당 역할 TOML을 읽어 하위 에이전트 작업 메시지에 지침을 전달한다. 새 설정의 자동 발견 여부와 관계없이 PM 보고 체계를 유지한다.

## 배정과 검수

PM은 다음 형태로 업무를 배정한다. 작은 수정은 짧은 메시지로 작성하면 된다.

```text
작업 ID:
담당 역할:
목표 / 완료 조건:
허용 수정 파일:
API·데이터 계약 / 선행 의존성:
검증 방법:
PM에게 반환할 결과:
```

기획 → 계약 확정 → 필요한 구현 → 안정된 변경 상태의 QA → 결함 수정·재검증 → PM 통합·커밋·푸시·사용자 보고 순서로 진행한다. 프론트·백엔드는 계약이 정해지고 파일이 겹치지 않을 때 병렬 진행한다. 같은 파일, DB, 포트, 서버 재시작은 PM이 순서를 정한다. QA는 완료된 변경을 독립적으로 검증하며 개발자의 주장만으로 통과하지 않는다.

## 다른 PC / 새 채팅

1. 저장소를 내려받고 **SwpPirateTcgShop 폴더 자체**를 Codex 작업 폴더로 연다.
2. 프로젝트를 신뢰한 상태에서 새 채팅을 시작한다. 실행 중인 세션의 제한이 설정 파일 작성만으로 갱신된다고 가정하지 않는다.
3. 기본 채팅은 PM 역할로 요청을 받고, 필요한 작업을 네 전문가에게 배정한다.
4. 실행 환경이 전문가 네 명의 동시 실행을 허용하지 않으면 PM이 같은 역할을 순차적으로 호출한다. 다섯 역할 구성과 다섯 개의 상시 실행 프로세스는 다르다.
5. 사용자 로그인·이용 동의가 필요한 경우 PM이 사용자에게 요청한다. 다른 전문가는 대신 승인하거나 비밀 값을 출력하지 않는다.

별도의 OpenAI API 프로그램이나 자동 상주 데몬을 추가하지 않는다. Codex가 제공하는 하위 에이전트 도구와 프로젝트 지침으로 운영한다.

설정 형식 참고: [OpenAI 공식 Subagents 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents).
