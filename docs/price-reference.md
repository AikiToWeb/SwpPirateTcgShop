# 가격 참조 규칙과 구현 범위

PRICE-PLAN · 확인일 2026-11-03. 아래에서 이번 구현과 후속 정책을 구분한다. 외부 사이트의 실시간 연동 성공을 이 문서만으로 보증하지 않는다.

## 이번 버전의 동작

가격 결정은 **관리자 조회 → 후보 검증 → 명시적 ‘기본가격 적용’ → 기존 상품 저장** 순서의 일회성 기능이다. 조회 API가 상품 판매가를 변경하지 않는다. 자동 가격 모드, 주기 갱신, 미입력 상품의 자동 판매가 결정은 이번 범위가 아니다.

- 판매자가 입력한 가격을 그대로 유지한다. 조회·조회 실패·재시작만으로 기존 수동가를 덮어쓰지 않는다. ‘기본가격 적용’은 검증된 후보를 편집 중 판매가 입력란에 넣으며, DB 반영은 관리자가 별도로 상품 저장을 해야 한다. 판매자는 적용 후에도 가격을 직접 수정할 수 있다.
- `tcgrollingdice.com`, `cardnyang.com`에서 같은 상품을 가리키는 사이트별 URL을 관리자가 매핑한다. 사이트 전체 자동 검색이 아니다. URL이 없거나 지원 형식이 아니면 `NEEDS_MAPPING`으로 표시하고 미등록으로 처리하지 않는다.
- `rollingAbsent`, `cardnyangAbsent`는 **관리자가 해당 판매처의 동일 상품 미취급을 직접 확인했다는 진술**이다. 체크 시 그 출처가 `NOT_FOUND`로 기록되지만, 자동 검색이 정상 완료되어 미등록임을 발견한 결과는 아니다. URL과 미취급 확인을 동시에 지정하면 검토가 필요하다.
- 두 출처의 동일 상품 유효 후보가 있으면 최저가를 권고한다. 한 출처가 유효하고 다른 출처가 관리자 미취급 확인이면 유효 후보를 권고할 수 있다. 한 출처라도 매핑 누락·통신 오류·파싱 불확실 상태이면 다른 후보가 있어도 전체 권고 및 적용을 보류한다.
- 양쪽이 모두 관리자 미취급 확인일 때만 네이버 수동 참조를 사용한다. 양쪽 URL 미입력, 품절, 통신 실패는 네이버 진입 조건이 아니다.
- 네이버 후보는 정확한 HTTPS 스마트스토어/브랜드스토어 상품 URL, 양수 가격, 관리자의 동일 상품 확인, **미래가 아닌 최근 24시간 이내 직접 확인 시각**이 필요하다. 별도 네이버 크롤러·자동검색은 구현하지 않는다. 관리자 입력 관측값을 자동 수집 시세와 구분한다.
- 조회 결과는 `price_reference_checks`에 기록한다. 직접 페이지 수집과 네이버/미취급의 관리자 확인은 출처·결과 사유로 구분한다. 페이지 캐시 재사용 시 실제 수집 시각을 유지하며, 결과의 `checkedAt`은 기여한 관측 중 가장 오래된 시각이다. 페이지 캐시는 현재 5분이고 주기적 갱신 작업은 아니다.

## 동일 상품과 가격 기준

게임, 상품명/영문명, 세트·상품 코드, 언어, 컨디션, 버전이 맞는지 확인한다. 현재 파서가 일반 싱글과 지원된 밀봉 상품 구조에서 검증 가능한 항목만 후보로 사용한다. 포일·패러렐·프로모·다른 아트·감정품처럼 정확한 동일성을 보장하지 못하면 추측하거나 다른 버전 가격을 대신 쓰지 않는다.

상품 형태는 `SINGLE`, `PACK`, `BOX`, `DECK`, `CASE`다. `unitCount`는 **해당 형태로 판매하는 묶음 수**다. 1덱=1, 1박스=1이며 덱 안 카드 수나 박스 안 팩 수가 아니다. 싱글 1장·팩·박스·덱·케이스 및 수량 다른 묶음끼리는 비교하지 않고 임의 단가 나누기로 환산하지 않는다. 현재 일반 싱글 자동 검증은 묶음 수 1만 지원한다.

비교 가격은 원화 상품 표시 판매가이며 배송비를 제외한다. 조건부 쿠폰·카드사·회원 할인은 일반 가격에 섞지 않는다. 참조 가격은 양수여야 하며 0원, 품절·재고 미확인, 예약·개봉·중고 여부나 옵션이 불명확한 상품은 권고 후보로 확정하지 않는다.

## 상태의 의미

| 상태 | 이번 구현에서의 의미 | 판매가 영향 |
|---|---|---|
| `READY` | 비교 가능한 후보 또는 조건을 갖춘 네이버 수동 관측값 | 명시적 적용 버튼만 사용 가능; 별도 상품 저장 전 DB 불변 |
| `NOT_FOUND` | 관리자의 해당 사이트 미취급 확인 | 자동 미등록 검색 결과가 아님 |
| `NEEDS_MAPPING` | URL 없음·지원 URL/호스트 형식 아님 | 적용 보류, 기존가 유지 |
| `NEEDS_REVIEW` | 동일성·단위·옵션·양수 가격·시각 검증 불충분 | 적용 보류, 기존가 유지 |
| `UNAVAILABLE` | 통신·응답 검증 실패, 품절/재고 미확인 또는 네이버 수동 입력 부족 | 사유 확인; 미등록·0원으로 바꾸지 않음 |
| `NO_MATCH` | 사용할 수 있는 유효 후보 없음 | 적용하지 않음 |

`READY`도 모든 출처가 자동 조회됐다는 뜻은 아니다. 네이버는 항상 관리자 수동 확인이며, 두 판매처의 `NOT_FOUND` 역시 관리자 확인이다. 입력 상품·언어·컨디션·단위·URL 등이 바뀌면 이전 조회 결과로 적용할 수 없어야 한다.

## 네이버 공식 자료와 미검증 범위

[쇼핑 검색 레퍼런스](https://developers.naver.com/docs/serviceapi/search/shopping/shopping.md)는 여전히 `shop.json` 명세를 게시하며 과거 응답의 `lprice=0`은 가격 정보 없음을 뜻한다. 그러나 [종료 공지](https://developers.naver.com/notice/article/32564)와 [이관 공지](https://developers.naver.com/notice/article/32530)는 쇼핑 검색 API가 **2026-07-31 종료**, 기존 키 유예와 NAVER API HUB 대체가 없다고 명시한다. 남아 있는 명세를 현재 지원 근거로 삼지 않는다.

[커머스API 인증](https://apicenter.commerce.naver.com/docs/commerce-api/current/exchange-sellers-auth)·[상품 목록 조회](https://apicenter.commerce.naver.com/docs/commerce-api/current/search-product)는 인증된 판매자 리소스용이며 임의 타 스토어 전체의 공개 경쟁가격 검색 대체 경로로 취급하지 않는다.

2026-11-03 사용자가 제공한 [스마트스토어 상품](https://smartstore.naver.com/cardnyang/products/13822971982)을 검증했다. 서버 공개 GET은 HTTP 429를 반환했지만 Codex 브라우저에서는 로그인 없이 ‘볼사리노 / SR / EB04-058’, 한글판 1장, 표시 판매가 55,000원을 확인했다. 이 금액은 당시 관측값이며 초기 상품 데이터나 고정 시세로 저장하지 않았다. 브라우저 열람 성공은 서버 자동 수집 성공을 뜻하지 않는다. 현재 서버 수집의 안정성을 검증하지 못해 수동 참조를 유지한다. 차단 우회·비공개 API·CAPTCHA 자동 처리는 구현하지 않았다.

## 현재 인수 조건

- 수동가 15,000원과 조회 후보 10,000원이 있어도 조회만으로 입력란과 DB의 15,000원이 바뀌지 않는다. ‘기본가격 적용’ 후 입력란만 바뀌고, 상품 저장 후에만 DB에 반영된다.
- 동일 상품 두 유효 후보 12,000원·10,000원에서는 10,000원을 권고한다. 한 곳 유효+다른 곳 관리자 미취급 확인은 남은 후보를 사용하고, 한 곳 오류/미매핑이면 적용을 보류한다.
- 더 싼 다른 언어·포일·컨디션·팩/박스/덱/케이스·묶음 수의 가격을 섞지 않는다. 1덱의 `unitCount=1`을 내부 카드 수로 오해하지 않는다.
- 0원·차단 HTML·타임아웃·파싱 실패·품절을 미등록으로 저장하지 않는다. 두 URL이 없다는 이유만으로 네이버로 넘어가지 않는다.
- 양쪽 미취급 체크는 사용자 직접 확인으로 표시한다. 네이버 가격도 직접 확인한 값임을 표시하며, 24시간 초과·미래 시각·잘못된 상품 URL·확인 누락은 적용을 막는다.
- 상품 정보·참조 입력 변경 시 기존 결과를 무효화하고, 늦게 도착한 이전 응답으로 다른 상품 가격을 적용하지 않는다.
- 검증은 별도 테스트 DB와 응답 fixture로 수행하고 운영 가격·상품을 만들거나 변경하지 않는다.

## 후속 정책 제안 — 현재 미구현

상시 자동 가격 모드, 수동가 잠금 해제와 자동 전환, 정기 수집, URL 자동 탐색, 네이버 상품 페이지 수집, 속성·감정등급의 추가 검증, 미확정 가격 상품의 공개·주문 차단 정책은 별도 요구사항·인수 조건을 정한 뒤 진행한다. 이들을 현재 구현 또는 연동 완료로 보고하지 않는다.
